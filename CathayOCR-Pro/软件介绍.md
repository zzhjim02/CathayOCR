# 古籍 OCR 助手 — PDF 批量转文字工具

> **不用学编程，不用配环境。双击打开，拖入 PDF，点一下开始，等几分钟拿到文字。**

---

## 这是干什么的？

你有一批古籍/文献的 **PDF 扫描件**（或者图片扫描成的 PDF），想把里面的**文字提取出来**变成可以搜索、复制、编辑的文本文件。

传统做法是：打开 PDF → 截图 → 一张张手动打字 → 太累了。

这个工具帮你**全自动做完**——你只需要告诉它哪几个 PDF 文件要处理，剩下的事它自己干。

---

## 谁需要用？

- 📜 **古籍研究者** — 校勘记、地方志、家谱、碑帖整理
- 🏛️ **图书馆/档案馆工作人员** — 批量扫描件数字化
- 👩‍🏫 **历史/中文系师生** — 文献研究，需要可检索的文本版本
- 📖 **文史爱好者** — 整理家谱、旧书、手稿
- 🌍 **多语言文献工作者** — 处理法文、德文、日文、俄文、韩文、阿拉伯文等多语种 PDF

## 怎么安装？

**什么都不用装。** 便携包里自带 Python 3.10、CUDA 库、所有依赖库和 OCR 模型，解压完直接运行。

```
1. 下载 Pro 专业版压缩包（约 5.8 GB）
2. 右键 → 解压到当前文件夹（建议解压到 SSD 硬盘）
3. 打开解压后的文件夹，找到「CathayOCR Pro.exe」
4. 双击它
5. 先弹出「运行日志」窗口，自动做一遍硬件自检（CPU / 内存 / 显卡），随后主界面弹出来
6. 看到主界面就可以用了（老方式「启动.bat」仍在，作为备用）
```

> ℹ **关于 CUDA**：便携包已内置 CUDA/cuBLAS/cuDNN DLL（约 2.4 GB）。有 NVIDIA 显卡的机器插上就能用 ONNX CUDA 引擎，无需单独安装 NVIDIA CUDA 工具包。
>
> ⚠ **如果杀毒软件报毒**：这是正常的误报，因为程序里调用了命令行程序和 Python 脚本。点击「允许运行」即可。

## 怎么用？超详细手把手教程

### 第一步：打开程序

双击 `CathayOCR Pro.exe`。先弹出的是「运行日志」窗口（显示启动过程、**硬件自检结论**、识别进度和报错），几秒后主界面出现。日志窗口**随手关掉也不要紧**，后台任务照常跑；想再看就再双击一次 exe。原来的 `启动.bat` 仍然可用，作为备用启动方式。

### 第二步：选择模式（🎯 简单模式  vs  🔧 专业模式）

界面左上角有两个选项：

- **🎯 简单模式**（**推荐新手**）— 回答 3 个问题 + 选个语言，系统自动配好一切参数
- **🔧 专业模式** — 每个参数自己调，适合有经验的高级用户

**刚开始用？直接默认就是🎯简单模式，继续往下看。**

### 第三步：简单模式三问（10 秒搞定）

#### ① 文档类型

| 选哪个 | 什么时候选 |
|-------|-----------|
| 📜 古籍/校勘 | 竖排繁体、校勘记、地方志——**古籍类文档必选** |
| 📄 普通文档 | 横排印刷品、现代书籍、论文 |
| 🗂️ 扫描件 | 没有 OCR 层的扫描件、拍照文档 |

#### ② 精度/速度

| 选哪个 | 效果 | 速度 |
|-------|------|------|
| 🎯 精度优先 | 最准确 | 慢一些 |
| ⚖️ 平衡（默认） | 够用 | 快 |
| 🚀 速度优先 | 还行 | **最快** |

#### ③ 显卡选择

| 选哪个 | 什么意思 | 普通语言走哪个引擎 |
|-------|---------|------------------|
| NVIDIA ≥12 GB | 大显存 NVIDIA（如 RTX 3060 12G / 4070 / 4080） | **PP-OCRv6 CUDA**（精度最高） |
| NVIDIA ≤8 GB | 小显存 NVIDIA（如 RTX 3050/4060/5060 8G） | **ncnn Vulkan**（省显存、可双实例更快） |
| AMD / Intel ≥12 GB | AMD Radeon / Intel Arc 大显存独显 | **ncnn Vulkan**（精度优先时边长 2560） |
| AMD / Intel ≤8 GB | AMD Radeon / Intel Arc 小显存独显 | **ncnn Vulkan**（精度优先时边长 2240） |
| 纯核显 / CPU | 没独显，或者用 AMD Vega / Intel UHD 之类 | **ncnn Vulkan**（把「模式」切到 **CPU模式**） |
| 🤷 我不知道 | 系统自动检测，选最优配置 | 按检测结果落上面某一档 |

> 💡 **注意**：CUDA 能力**与显存大小无关** —— 8GB 的 N 卡同样能跑 CUDA 引擎。NVIDIA 的档位只决定"普通语言用哪个引擎"：大显存换精度，小显存用 Vulkan 换速度与显存余量。**勾选 ⚠ 语言时，任何 NVIDIA 卡都会自动切到 PP-OCRv6 引擎**。
> 💡 AMD / Intel 显卡**没有 CUDA**，所以分大小两档的差别**只在"精度优先"时的图像边长**（≥12GB 用 2560，≤8GB 用 2240 防爆显存），引擎都是 ncnn Vulkan。

#### ④ 文档语言（🌐 勾选，可多选）

语言从 82 项合并为 **13 组**并改为**多选勾选框**：把文档里**可能出现的语言都勾上**（例如「中文 + 英文 + 日文」），系统据此选引擎。

| 勾选项 | 说明 |
|-------|------|
| 中文 / 英文 / 日文 | 主力引擎通用字典直接支持 |
| 拉丁语系 (法德西意等) | 法/德/西/意/葡/荷… 40+ 种拉丁字母语言 |
| 希腊文 | ncnn 字典含 76 个希腊字符，实测可识 |
| **韩文⚠ / 西里尔文系⚠ (俄/乌/保等) / 阿拉伯文系⚠ (阿/波/维/乌等) / 天城文系⚠ (印地/马拉地等) / 泰文⚠ / 泰卢固文⚠ / 泰米尔文⚠** | 这些文字**不在** v6/ncnn 通用字典里，勾选后自动切换专用分语种模型（见下） |
| 多语言混排 (中·英·日 + 拉丁语系) | 混合排版文档（中英日 + 法德西意等）；主力引擎通用字典直接覆盖，**不需要切换引擎** |

> ⚠ **勾选带 ⚠ 的组会发生什么**：系统自动切换到专用分语种模型 —— **NVIDIA 显卡**（不限显存）用 **PP-OCRv6 引擎自动回退官方 v5 分语种模型**；**AMD/Intel/纯 CPU** 用 **PP-OCRv5 (Paddle CPU) 备选引擎**。配置摘要栏会明确提示"已切换"。
> 💡 **勾选语言只用于决定"用哪个引擎/模型"，不会改变识别结果的语言范围** —— 主力引擎本就是通用字典，勾不勾都认；勾选的真正作用是：一旦出现 ⚠ 组，就提前把引擎切到能认它的那一个，避免乱码。

### 第四步：添加文件

把 PDF 文件**拖进去**（直接拖到文件列表空白区域），或者点击「添加PDF文件」按钮选文件。可以一次选多个。

### 第五步：选输出目录

点击「选择输出目录」，告诉程序把识别结果放在哪里。不选的话默认放在 PDF 文件同目录。

### 第六步：点「开始处理」

然后等着就行。进度条会告诉你处理了多少。

> 🪟 **想边处理边用电脑、又不想被大窗口占地方？** 点顶部的「**迷你窗口**」按钮，主界面和日志窗口会一起收成屏幕**右下角**的一张悬浮小卡片：上面一行「**本文件**」是当前 PDF 的页进度（识别到第几页），下面一行「**总进度**」是本批已处理 / 总文件数。识别照常跑，完全不影响。
>
> 处理**完成后会自动还原**成完整窗口；也可以随时点卡片上的「恢复」、双击卡片、或点任务栏图标把它叫回来。卡片标题栏的「📌」可以切换是否**总在最前面**，卡片本身也能拖到任意位置。
>
> 如果**还没开始处理**就点了「迷你窗口」，卡片上会写「等待用户安排 OCR 任务」。

### 第七步：看结果

处理完成后，输出目录里会出现：
- `XXX_result.txt` — 识别的纯文字（记事本打开就能看）
- `XXX_layered.pdf` — 带文字层的 PDF（可以在里面选中文字、复制、搜索）

## 快速参考

### 引擎怎么选？（简单模式全自动）

> 📘 完整规则见同目录 `引擎规则说明.md`。

简单模式下你**不用管引擎**，只要如实回答"显卡是哪种 + 文档里有哪些语言"，系统按下面两条路径自动决定：

**① 普通路径**（未勾选任何 ⚠ 语言：中/英/日/拉丁/希腊文）

| 你的显卡 | 自动选用的引擎 | 为什么 |
|------------|-----------|------|
| **NVIDIA ≥12GB** | **PP-OCRv6 ONNX CUDA** | 显存充足，用最高精度模型 |
| **NVIDIA ≤8GB** | ⭐ **ncnn Vulkan** | 显存省、可开双实例，批处理更快（约 2.2 页/秒） |
| **AMD / Intel ≥12GB** | ⭐ **ncnn Vulkan** | 唯一可用的 GPU 加速选项（精度优先时边长 2560） |
| **AMD / Intel ≤8GB** | ⭐ **ncnn Vulkan** | 同上（精度优先时边长 2240，防爆显存） |
| **纯核显 / CPU** | **ncnn Vulkan**（模式切 **CPU**） | 兼容性最好，速度最慢 |

**② ⚠ 专用路径**（勾选了 韩文/西里尔/阿拉伯字母/天城文/泰/泰卢固/泰米尔 任一组）

| 你的显卡 | 自动选用的引擎 | 说明 |
|------------|-----------|------|
| **任意 NVIDIA**（≥12GB 或 ≤8GB） | **PP-OCRv6 ONNX CUDA** | 引擎自动回退到官方 **PP-OCRv5 分语种模型**（韩文 88% 准确率）；该模型目前走 CPU 推理，约 3 秒/页 |
| **AMD / Intel 独显 / 核显 / 纯 CPU** | **PP-OCRv5 (Paddle CPU)** | 内置 11 套官方分语种模型，纯 CPU 兜底 |

> 💡 **为什么 ⚠ 语言不能留在 ncnn 引擎？** 实测 ncnn 的 v6 通用字典对这 7 类文字**覆盖为 0 字符**，照样跑只会输出乱码。软件已自动帮你切换，并在配置摘要里提示。
> 💡 **专业模式**下若手动把引擎与语言配错（如 ncnn + 阿拉伯文），点「开始处理」时会**弹窗拦截提醒**，避免静默乱码。
> 💡 **不知道有没有独立显卡？** 打开任务管理器（Ctrl+Shift+Esc）→ 性能 → 看左边有没有多个「GPU」。如果有 GPU 0 和 GPU 1，说明有独立显卡。

### 语言选哪个？

> 简单模式是**多选框**，把文档里可能出现的语言**都勾上**即可（如"中文 + 英文"）；下表是"该选哪一个组"的对照。

| 你的 PDF 是什么文字 | 勾选 |
|-------------------|--------|
| 中文古籍（繁简体都行） | **中文** — 一个选项覆盖繁简体 |
| 日文古籍 / 日本文献 | **日文** |
| 法文 / 德文 / 西班牙文 / 意大利文等 | **拉丁语系 (法德西意等)** |
| 希腊文 | **希腊文**（通用字典含希腊字符，不切换引擎） |
| 韩文文献 | **韩文⚠** → 自动切专用模型（v5 韩文模型，88% 准确率） |
| 俄文 / 乌克兰文 / 保加利亚文等 | **西里尔文系⚠** → 自动切 **PP-OCRv5 (Paddle CPU)** 引擎（实测比 v6 引擎的 ONNX 版更准，且快约 5 倍） |
| 阿拉伯文 / 波斯文 / 维吾尔文 / 乌尔都文 / 普什图文 等 | **阿拉伯文系⚠** → 自动切专用模型 |
| 印地文 / 马拉地文 / 尼泊尔文 / 梵文 / 博杰普尔文 等 | **天城文系⚠** → 自动切专用模型 |
| 泰文 / 泰卢固文 / 泰米尔文 | 各自勾选对应 ⚠ 项 → 自动切专用模型 |
| 中文+英文+日文+拉丁系混排 | **多语言混排 (中·英·日 + 拉丁语系)** — 通用字典覆盖，不切换 |
| 混排里还含 韩/俄 等 ⚠ 文字 | **多语言混排 + 同时勾上对应的 ⚠ 组** |
| 欧洲 46 种拉丁语系混合 | 勾 **拉丁语系** 即可 |

> 💡 简单模式勾选只决定"用哪个引擎/模型"。若切到专业模式，语言下拉会**自动落到对应的完整语种项**（如"阿拉伯文系"→"العربية (阿拉伯文)"），共 82 项。

## 常见问题（小白版）

### Q: 双击后没反应 / 黑框一闪就没了？
A: 解压不完整。确认 `portapython\python.exe` 文件存在，不要单独移动任何文件夹。先看「运行日志」窗口里报了什么错；若用的是备用方式 `启动.bat`，黑框一闪而过也是同一个原因。

### Q: 点了「迷你窗口」，程序好像不见了？
A: 它是收成了**屏幕右下角的小卡片**（不占任务栏），不是消失。右下角一时看不到，多半是被别的窗口压住了 —— 卡片上的「📌」可以切换置顶；也可以双击卡片、点卡片上的「恢复」，或点任务栏的程序图标还原。任务**跑完会自动还原**。

### Q: 进度不动了？
A: 点「停止」按钮，关掉程序，重新打开再试。偶尔单个页面比较难识别会卡住。

### Q: 识别出来的文字好多错误？
A: 检查下面几个：
1. 渲染倍率调到 **3x**
2. 图像边长调到 **3000**
3. 模型选 **v6 Server**

### Q: 速度太慢了？
A: 试试这几个：
1. 确认模式选了"自动"或"GPU模式"
2. 开启「双实例并行」
3. 精度选 FP16

### Q: 竖排文字识别不好？
A: 确认「竖排文字」是打勾的。如果还不好，图像边长加到 3000，渲染倍率调到 3x。

### Q: 这个和普通的 Umi-OCR 有什么区别？
A: 普通 Umi-OCR 更适合单张图片或少量文字的识别。这个工具是专门为**大量 PDF 文件**设计的，多了自动流水线、双实例并行加速、GPU 设备选择、简单模式等功能，批处理效率高得多。

## 简单说人话版

把这个工具想象成一个**自动抄书工**：

- 你把 PDF 书页丢给它
- 它自动翻页、拍照、认字、抄写
- 抄完后给你一份纯文字的电子版
- 你可以复制、搜索、修改里面的文字

它的速度取决于你给它配的"眼镜"（引擎和模型）：
- ⭐ **ncnn Vulkan** = ⭐首推！什么显卡都能加速，没显卡自动切 CPU，到哪里都能用
- **PP-OCRv6 (ONNX CUDA)** = 自带 CUDA 库，有 NVIDIA 显卡的电脑插上就能用
- **EasyOCR** = 备用（英/法/意/西四种拉丁语系）
- **ncnn Vulkan · CPU模式**（原「ncnn CPU」）= 什么电脑都能用；两者是**同一个引擎**，切「模式」即可

> **还不确定？选 🎯 简单模式，一切默认，开干就行。**
