## v1.2.4 更新内容（2026-09-11）

### 修复「除 Vulkan 外其他引擎全部不可用」（重要）

选择 ncnn Vulkan 以外的引擎（PP-OCRv6 ONNX / PP-OCRv5 / 经典版 / ncnn CPU / EasyOCR）时，引擎能启动、界面不报错，但导出结果**没有任何文字**：`_result.txt` 只有文件头、`_layered.pdf` 没有文字层。原因是 OCR 消费线程调用了**只存在于 Vulkan 适配器**上的 `get_dynamic_timeout()`，非 Vulkan 引擎立即抛 `AttributeError`，且该调用位于 try 之外 → 线程当场死亡、页面永不识别。

现已把 `get_dynamic_timeout()` 与 `restart()` 提升到基类通用实现，并让 Paddle / ncnn CPU 适配器同样记录耗时（动态超时升档、看门狗自愈对所有引擎生效），调用处加兜底。**ncnn Vulkan 行为零变化**。6 引擎真机端到端回归全部通过（PP-OCRv6 42 字 / PP-OCRv5 42 字 / 经典版 41 字 / ncnn CPU 42 字 / EasyOCR 88 字）。

> ⚠️ **注意**：该缺陷源自 v1.1.3 的看门狗实现，v1.2.3 未触及，因此在 v1.2.4 之前除 Vulkan 外的引擎实际不可用。

## v1.2.3 更新内容（2026-08-27）

### 1. 修复「竖排识别」无效的 Bug（重要）

原「竖排文字」选项是**无效开关**：参数链路层层传递却从未被引擎使用，竖排古籍结果始终按横排顺序输出。现在勾选「竖排识别」后按**中心点 X 降序（右→左）、Y 升序（上→下）** 重排，纯 CPU 后处理 <10ms。选项更名为「**竖排识别**」，默认不勾选。

### 2. 修复竖排文字写不进 PDF / 搜索不到的问题（重要）

竖排古籍检测框为「高>宽」竖条框，但导出时文字按横排写入 → 长句横向展开超出页面右边界，被查看器裁剪丢弃，PDF 搜不到、缺字。现在竖条框（高>宽）以 **rotate=270 从框顶向下竖排写入**，整句完整落在页面内可正常搜索。与「竖排识别」勾选联动。

### 3. 修复 OCR 坐标超界 Bug

OCR 返回 scale=2 渲染图像的像素坐标，写入 PDF 前未 ÷scale → 文字落页面外无法提取/搜索。已修复：`x0/=scale; y0/=scale; x2/=scale; y2/=scale`。

### 4. 新增「覆盖旧OCR」功能

勾选后导出双层 PDF 时**物理删除原 PDF 全部旧文字层**（PyMuPDF Redaction，保留图像层与矢量图形），只叠加本次新识别文字层，Ctrl+F 可正常搜索。

> ⚠️ **注意**：竖排古籍请勾选「竖排识别」；替换旧层请勾选「覆盖旧OCR」。两选项默认均不勾选。

## 附赠工具：TXT 文本层写回工具 v1.1

> 位置：`TXT写回工具\` 目录，双击 `启动工具.bat` 即可运行

### 它是什么？

一个**批量修复「双层 PDF 无法搜索」问题的独立小工具**。

很多古籍 PDF（网上下载或旧工具生成）带有**错误/无法搜索的隐藏文本层**——用 Chrome/Edge 打开时 Ctrl+F 搜不到字，但同名的 `_result.txt` / `_PD6AIFOCR.txt` 里却有完整 OCR 文字。

本工具把 TXT 里的识别结果**按页码重新写回 PDF**，替换掉错误的旧文字层，让 PDF 重新可搜索、可复制。

### 核心能力

- **按页码对应**：TXT「第 N 页」的内容写入 PDF 第 N 页，不依赖图像坐标
- **竖排古籍风格**：每页文字从右上角起，每行一列，列从右到左（rotate=270），符合古籍版式
- **透明文字层**：不影响看图，可正常复制/搜索
- **彻底清除旧层**：删除内容流中全部旧文字（含残留 TD 块），图像层无损
- **多核并行**：默认 4 线程同时处理多个文件，可调 1~16，处理 400+ 文件大幅提速
- **递归扫描**：选择任意父目录，自动扫描所有子目录配对
- **保留原件**：输出 `XXX_..._fixed.pdf`，不覆盖原文件
- **任意页面尺寸**：列宽/字号按页面尺寸动态计算，兼容 A4 与其它开本

### 自动识别的文件配对

| TXT                 | PDF                     | 来源                       |
| ------------------- | ----------------------- | ------------------------ |
| `XXX_result.txt`    | `XXX_layered.pdf`       | CathayOCR 输出             |
| `XXX_PD6AIFOCR.txt` | `XXX_PD6AIFOCR_opt.pdf` | FOCR 工具输出                |
| `XXX_PD6AIFOCR.txt` | `XXX_PD6AIFOCR.pdf`     | FOCR 无 \_opt 变体（如北洋政府公报） |

其它后缀（`_FOCR_opt.txt`、`_【繁转简】` 等）一律忽略。

### 使用步骤

1. 点 **选择目录**，选中存放配对文件的**任意父目录**（自动递归扫描所有子目录）
2. 列表显示配对的两个文件名（TXT 列 + PDF 列）与状态
3. （可选）修改输出后缀，默认 `_fixed`；调整「并行数」（默认 4，可调 1~16）
4. 点 **开始处理选中项**，输出文件在各 PDF 同目录生成 `XXX_..._fixed.pdf`
5. 在 Chrome/Edge 中打开即可搜索

## 核心特性

### 引擎管理（6 引擎统一注册）

通过 `ENGINE_REGISTRY` 统一管理，每个引擎声明入口文件、协议类型（管道 / TCP 持久连接 / 子进程）、GPU/CPU 支持、语言范围、可用参数。

| 适配器模式               | 说明                     | 对应引擎                                         |
| ------------------- | ---------------------- | -------------------------------------------- |
| `PaddlePipeAdapter` | 管道 JSON 协议，子进程标准输入输出   | PP-OCRv6 ONNX CUDA、EasyOCR、PP-OCRv5、PP-OCRv3 |
| `NcnnVulkanAdapter` | TCP 持久连接，Vulkan GPU 加速 | ncnn Vulkan                                  |
| `NcnnCPUAdapter`    | 子进程单次调用，纯 CPU          | ncnn CPU                                     |

### 双模式界面

- **🎯 简单模式**：只需回答 4 个问题（文档类型、精度速度、显卡、语言），自动映射全部专业参数。小白用户 10 秒完成配置。
- **🔧 专业模式**：全部参数自由调节，适合有经验的高级用户。

### 🪟 迷你窗口模式

处理中可以点顶部「🗕 迷你窗口」，把**主窗口与日志窗口一起收成一张 420×146 的圆角悬浮卡片**（停在屏幕右下角）：

- 卡片显示**两条进度**：
  - **本文件**：当前 PDF 识别到第几页（绿色进度条 + `第 3 / 12 页 (25%)`），与运行日志窗口里的页进度**同源**；
  - **总进度**：本批已处理 / 总文件数（蓝色进度条 + `已处理 12 / 40`）。
- 未开始处理时进入该模式，显示「等待用户安排 OCR 任务」
- **处理完成后自动还原**；也可随时点「恢复」按钮、双击卡片、或点任务栏图标手动还原（保留进入前的最大化状态）
- 卡片可任意拖动，标题栏「📌」可**手动切换置顶**（默认置顶，选择会被记住）
- 纯界面行为，**不影响 OCR 任务**：收起卡片时识别照常进行

### 双实例并行

启动两个独立 OCR 子进程轮询调度，GPU 模式下效果显著（Vulkan 可翻倍），CPU 模式下提升有限。CPU 模式自动禁用。

### GPU 加速

- **ncnn Vulkan**：跨厂商 GPU 支持（NVIDIA / AMD / Intel 任意品牌）。原生 CPU 回退，无 GPU 也能跑。
- **ONNX Runtime CUDA**：NVIDIA 专属加速。便携版已内置 CUDA DLL，无需系统安装 CUDA 工具包，即插即用。
- 启动时自动检测 GPU 设备，优先选中独立显卡。
- FP16 半精度推理（ncnn 引擎），显存占用减半，速度提升约 30%。

### 多语言支持

82 种语言/文字选项，涵盖 CJK、拉丁语系、西里尔语系、希腊文、阿拉伯文系、天城文系、东南亚文字（详见[语言支持范围](#语言支持范围)）。

### 容错机制

- **超时保护**：单页 OCR 超过 180 秒自动跳过
- **安全定时器**：整体任务无进度超过 300 秒触发紧急停止
- **进程清理三保险**：SIGTERM → `taskkill /f` → `atexit` 兜底
- **快速取消**：直接终止子进程，秒级响应

## 引擎对比与选型指南

| 评价维度       |    ncnn Vulkan ⭐   |      PP-OCRv6 ONNX CUDA      |      ncnn CPU     |
| ---------- | :----------------: | :--------------------------: | :---------------: |
| **速度**     |      ⭐⭐⭐⭐⭐ 最快      |            ⭐⭐⭐⭐ 快            |        ⭐⭐ 慢       |
| **识别精度**   |     ⭐⭐⭐⭐⭐（同模型）     |             ⭐⭐⭐⭐⭐            |        ⭐⭐⭐⭐       |
| **显卡兼容**   |       任意 GPU       |           仅 NVIDIA           |        不要显卡       |
| **CPU 回退** |        ✅ 原生        |             ✅ 支持             |        ✅ 原生       |
| **双实例效果**  |       优秀（显存低）      |            好（显存高）            |         一般        |

| **模型兼容**   |      v3~v6 全系列     |             固定 v6            |     v3~v6 全系列     |
| **语言覆盖**   | v6 通用字典（拉丁/CJK/希腊） | **全部**（通用字典 + ⚠ 回退 v5 分语种模型） | v6 通用字典（同 Vulkan） |

> ⚠ **重要说明**：ncnn Vulkan 和 PP-OCRv6 ONNX CUDA 的普通语言都用 PP-OCRv6 模型，**识别精度由所选模型版本决定，不取决于引擎**。同模型下 ncnn Vulkan 识别率略高。>   
> ⚠ **韩文/西里尔/阿拉伯/天城文/泰系在 ncnn 下必乱码**（字典 0 覆盖）：必须用 PP-OCRv6 CUDA（自动回退 v5 分语种模型）或 PP-OCRv5 (Paddle CPU)。

### 简单场景快速选择

| 你的情况                            | 推荐引擎                   | 理由                                        |
| ------------------------------- | ---------------------- | ----------------------------------------- |
| **有 NVIDIA 显卡，普通文档（中/英/法/德/日）** | ⭐ **ncnn Vulkan**      | 速度最快、省显存；大显存（≥12GB）可改选 PP-OCRv6 CUDA 换精度  |

| **无独显 / 纯核显**                   | **ncnn CPU**           | 稳定兼容；含 ⚠ 文字时改选 PP-OCRv5 (Paddle CPU)      |
| **不确定配置，就想快点上手**                | ⭐ 勾「🎯 简单模式」           | 回答 3 个问题 + 勾语言，全自动                        |

## 常见问题

### Q: 双击 `CathayOCR Pro.exe` 没反应 / 闪一下就没了？

A: 解压不完整。确认 `portapython\python.exe` 存在，不要单独移动文件或修改目录结构。先看「运行日志」窗口里的报错信息；若用备用方式 `启动.bat` 时黑框一闪而过，同样是解压不完整。

### Q: 点了「迷你窗口」，程序好像不见了？

A: 没有消失，是收成了**悬浮小卡片**，停在屏幕**右下角**（不占任务栏）。如果右下角一时看不到，可能是被别的窗口压住了 —— 卡片标题栏的「📌」按钮可以切换置顶；也可以双击卡片、点卡片上的「恢复」，或点任务栏的程序图标还原。处理**完成后会自动还原**。

### Q: 启动时提示"未检测到 CUDA"？

A: 这是正常提示（没有 NVIDIA 显卡或没有驱动时才出现）。选 ncnn Vulkan 引擎一样能 GPU 加速（AMD/Intel 显卡都可以）。

### Q: 进度不动了 / 卡住了？

A: 点击「停止」，关掉程序重新打开。如果频繁卡住：① 检查任务管理器里有没有残留的 OCR 进程；② 调低批处理数；③ 选 ncnn CPU 引擎试试。

### Q: 识别结果全是乱码？

A: 检查语言是否选对。如果选了中文但 PDF 是法文，请改语言。v6 模型引擎必须使用配套的 `ppocr_keys_v6.txt` 字典。

### Q: 速度太慢？

A: ① 确认模式是"自动"或"GPU模式"；② 打开「双实例并行」；③ 精度选 FP16；④ 调低渲染倍率到 1x。

### Q: 识别质量不好？

A: ① 渲染倍率调到 3x；② 图像边长调到 3000；③ 选 ncnn CPU 引擎（稳定）；④ 如果用 ONNX CUDA，试一下模型从 small 换 medium。

### Q: GPU 利用率很低（<50%）？

A: 开启双实例并行，提高批处理数（12~16）。Vulkan 双实例可以吃满 GPU。

### Q: 便携包太大（9 GB），能删些什么？

A: 可以安全删除的是：

- `ppocr_v3/` (300 MB) 和 `ppocr_v5/` (405 MB)——备胎引擎，大多数情况用不到
- `ncnn/models/` 里不需要的模型版本（v3/v4 约 100 MB 每个）
- `easyocr_data/` (1 GB) 删掉后仅拉丁语系备选识别受影响（韩/俄已改由 PP-OCRv5 分语种模型负责），非必需
- **不能删**：`portapython/`（运行核心）、`ppocr_v6/`（主力引擎 + ⚠ 语种回退）、`ppocr_v5/`（⚠ 语种在非 NVIDIA 机器上的备选）、`ncnn/`（主力引擎）

### GPU 兼容性速查

| GPU                 | ncnn Vulkan | PP-OCRv6 ONNX CUDA | 推荐                                                                                             |
| ------------------- | :---------: | :----------------: | ---------------------------------------------------------------------------------------------- |
