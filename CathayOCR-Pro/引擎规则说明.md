# CathayOCR Pro 引擎与参数选择规则（v1.3.0）

> 本文是引擎/参数自动选择规则的**单一事实来源**，与代码逐条对应（`CathayOCR-Pro/umi_ocr_pdf_processor_ui.py`、
> `ppocr_v6/ppocr_v6_server.py`）。简单模式全自动；专业模式全手动 + 开跑前守卫。

---

## 一、简单模式：4 个问题 → 全部参数

### Q1 文档类型 → 竖排检测 / 方向纠正

| 选择 | 竖排检测 | 方向纠正 |
|---|---|---|
| 普通文档（横排印刷体） | 关 | 关 |
| 古籍竖排（繁体/竖排/复杂排版） | **开** | 关 |
| 扫描件/照片（可能方向不正） | 关 | **开** |

> 文档类型**不再决定边长与渲染倍率**——这两项统一由「精度档 + 显存档」决定（见 Q3）。
> 渲染倍率只有一种情况会用到 3x：**古籍 + 精度优先 + 大显存（或纯CPU）**。

### Q2 精度与速度 → 模型参数

| 选择 | 模型 | 批处理数 | 浮点精度 | 对齐 shrink |
|---|---|---|---|---|
| 速度优先 | v6 small | **16** | FP16 | 关 |
| 标准平衡（推荐） | v6 medium | **16** | FP32 | 关 |
| 精度优先 | v6 medium | **16** | FP32 | **开** |

> **批处理数与精度档无关**，三档统一 **16**（常量 `_SIMPLE_REC_BATCH`），不再随档变化。

### Q3 显卡 → 引擎 + 运行模式 + 边长 + 渲染倍率

下拉 6 档：`0` NVIDIA ≥12GB ／ `1` NVIDIA ≤8GB ／ `2` AMD·Intel ≥12GB ／ `3` AMD·Intel ≤8GB ／ `4` 核显·纯CPU ／ `5` 自动检测

**引擎 / 运行模式**

| 档位 | 运行模式 | 普通语言引擎 |
|---|---|---|
| 0 NVIDIA ≥12GB | auto | PP-OCRv6 (ONNX CUDA) |
| 1 NVIDIA ≤8GB | auto | PP-OCR ncnn Vulkan |
| 2 AMD/Intel ≥12GB | auto | PP-OCR ncnn Vulkan |
| 3 AMD/Intel ≤8GB | auto | PP-OCR ncnn Vulkan |
| 4 核显·纯CPU | **cpu** | PP-OCR ncnn Vulkan（**CPU 模式**，即 `use_gpu=False`） |

> `ncnn_cpu` 已**合并**进 `ncnn_vulkan`：两者的可执行文件是**同一份**（`ppocr_ocr_cpu.exe` 与
> `ppocr_ocr_vulkan.exe` 的 MD5 完全相同），CPU 运行统一由 ncnn Vulkan 的「CPU模式」承担，
> 因此引擎下拉里**不再有**单独的「PP-OCR (ncnn CPU)」项。

双实例：非纯 CPU 档默认**开**；纯 CPU 档自动**关**（无增益）。

**边长与渲染倍率（定稿）**

| 速度档 / 显存档 | 边长 | 渲染倍率 |
|---|---|---|
| 速度优先 | **2240**（一律） | **2x** |
| 标准平衡 | **2240**（一律） | **2x** |
| 精度优先 · **大显存**（档 0/2）或纯CPU（档 4） | **2560** | 古籍 → **3x**；其余 → 2x |
| 精度优先 · **小显存**（档 1/3） | **2240** | **2x** |

- 大显存档 = `{0, 2, 4}`（NVIDIA ≥12GB ／ AMD·Intel ≥12GB ／ 纯CPU）；小显存档 = `{1, 3}`
- 渲染 **3x 的唯一触发条件**：古籍竖排 + 精度优先 + 大显存（或纯CPU）。其余一律 2x，**不再有 X3**
- 自动检测（档 5）落点：`nvidia-smi` 显存 ≥11000 MiB → 0，否则 → 1；无 N 卡但有 Vulkan 独显 → **3**（Vulkan 探测读不到显存，AMD/Intel 一律保守按小显存档）；只有核显 / 探测失败 → 4

> ⚠ **CUDA 能力与显存大小无关**：8GB 的 N 卡一样能跑 CUDA。档位只决定"**普通语言用哪个引擎**"以及**精度优先时的边长**。

## 二、引擎决策（两条路径）

设 `nvidia = 档位 ∈ {0, 1}`（任意 NVIDIA 卡都具备 CUDA）。

### 路径 A：普通路径（未勾选任何 ⚠ 组）

| 档位 | 引擎 |
|---|---|
| 0 NVIDIA ≥12GB | **PP-OCRv6 (ONNX CUDA)** — 用 CUDA 换最高精度 |
| 1 NVIDIA ≤8GB | **PP-OCR ncnn Vulkan** — 省显存、可双实例，批处理更快 |
| 2 AMD/Intel ≥12GB | **PP-OCR ncnn Vulkan** |
| 3 AMD/Intel ≤8GB | **PP-OCR ncnn Vulkan** |
| 4 核显/纯CPU | **PP-OCR ncnn Vulkan（CPU 模式）** — 同一二进制，`use_gpu=False` |

> 为什么 ≤8GB 走 Vulkan：显存占用低、双实例加速，实测约 2.2 页/秒（CUDA 约 1.1 页/秒）。
> AMD/Intel 卡没有 CUDA，**一律走 Vulkan**（显示分档只影响精度优先时的边长）。

### 路径 B：⚠ 专用路径（勾选了任一 ⚠ 组）

| 档位 | 引擎 | 说明 |
|---|---|---|
| 主语言 = **西里尔文（俄/乌/保）** | **PP-OCRv5 (Paddle CPU)** | **任何显卡都走它**（2026-10-09 起调整，依据见下） |
| 主语言 = 其它 ⚠ 组，0 / 1（任意 NVIDIA） | **PP-OCRv6 (ONNX CUDA)** | 引擎**自动回退官方 PP-OCRv5 分语种模型**；分语种模型目前走 CPU 推理，实测约 3 秒/页 |
| 主语言 = 其它 ⚠ 组，2 / 3 / 4（非 NVIDIA） | **PP-OCRv5 (Paddle CPU)** | 纯 CPU 备选，内置 11 套官方分语种模型 |

> 这 7 类文字在 ncnn 通用字典里**实测 0 字符覆盖**，留在 ncnn 必乱码，所以必须切引擎。
> "NVIDIA → v6 引擎"只表示**选用哪个引擎**（v5 分语种模型只有 v6 引擎能调），不代表独占 GPU 加速。
>
> **为什么西里尔文单独走 Paddle CPU**（2026-10-09 真机实测，12 张俄/乌克兰图）：
> v6 引擎的 ONNX 版分语种模型（`eslav`、`cyrillic` 都试过）会把 «Русский» 认成
> «Russkiy»（11/12 张正确）；`win7_v5` 的 Paddle Inference 版同款 eslav 模型
> **12/12 全对**。且 v6 引擎的 v5 分支本来就强制 CPU（ORT），两边速度同量级——
> 实测 12 页 42.3s（v6 引擎）vs 7.9s（Paddle），**换引擎反而快 5 倍**。
> 韩/阿/天城/泰等不受影响：韩/泰两引擎逐字一致，阿拉伯文 v6 引擎反而语序更对。

### 降级链（引擎缺失时）

⚠ 路径下若 v6 引擎不可用 → `win7_v5` → `ncnn_vulkan`（取第一个可用）；西里尔主语言直接取 `win7_v5`。

配置摘要栏会明示：`⚠ 已切换：勾选⚠语言 → PP-OCRv6 引擎自动回退分语种模型`（或 `→ PP-OCRv5 (Paddle CPU) 备选引擎`；西里尔文显示 `⚠ 已切换：西里尔文 → PP-OCRv5 (Paddle CPU) 引擎（实测比 v6 引擎的 ONNX 版更准且更快…）`）。

## 三、专业模式

引擎、设备、模型、语言全部自由组合（下拉共 **5 个引擎**：`umi_plugin_v6` / `ncnn_vulkan` / `win7_v5` / `win7_classic` / `easyocr_universal`）。

### 3.1 语言下拉按引擎过滤（不再列出必乱码的文字）

| 引擎 | 语言下拉内容 |
|---|---|
| `umi_plugin_v6` | **全部 82 项**（v6 普通语言 + v5 分语种回退全覆盖） |
| `win7_v5` | **全部 82 项**（按语言路由到官方分语种模型） |
| `ncnn_vulkan` | 仅 **v6 通用字典真正覆盖**的 50 项：中/英/日/拉丁/希腊 + 多语言混排；**不列出**韩文、西里尔、阿拉伯、天城文、泰/泰卢固/泰米尔 |
| `easyocr_universal` | 仅 英 / 法 / 意 / 西 4 项 |
| `win7_classic` | 中文（单模型，下拉置灰） |

- 过滤用的集合 `_NCNN_UNSUPPORTED`（**32 项** = 韩1 + 西里尔13 + 阿拉伯8 + 天城7 + 泰/泰卢固/泰米尔3）
  与开跑守卫**共用同一份**，避免"下拉能选、守卫又拦"的自相矛盾。
- 希腊文（`el`）**不在**排除集 —— 实测 v6 字典含 76 个希腊字符，可直接识别。
- 「多语言混排（中·英·日 + 拉丁）」与「多语言混排（46 拉丁）」**也不排除**（都在 v6 字典覆盖内）。
- ⚠ 2026-10-09 修正：v6 引擎下「多语言混排（46 拉丁）」**会**切到 PP-OCRv5 latin 模型，不再算
  "共用同一份 v6 模型" —— 语言下拉里它已从第一组挪到第二组。
  （此前它传 `lang="latin"`，paddleocr 3.6 的语言表里没有这个字面值，会直接
  `ValueError: No models are available` → 引擎初始化失败、界面无任何输出；
  现改传 `lb`（卢森堡文，LATIN_LANGS 成员且不在 v6 语言表）精确命中
  `latin_PP-OCRv5_mobile_rec`，GUI 实跑已恢复正常输出。）

### 3.2 模型下拉

| 引擎 | 模型下拉 |
|---|---|
| `umi_plugin_v6` | 高精度 (Medium) / 快速 (Small) |
| `ncnn_vulkan` | 运行时扫描（v6 server/medium/small/tiny、v5 server/mobile、v4、v3） |
| `win7_v5` | **「按语言自动选择 (官方分语种模型)」并置灰** —— 模型由「语言」决定，不是在这里选 |
| `win7_classic` | 中文 (默认)，置灰 |
| `easyocr_universal` | 自动 (按语言选择) |

### 3.3 引擎 ↔ 语言 不匹配的提示与跳转

两处会提示，且都可**一键跳转到推荐引擎**（推荐规则：NVIDIA 机器优先 `umi_plugin_v6`，否则 `win7_v5`）：

1. **切换引擎时**：新引擎不支持当前所选语言 → 弹窗「是否切换到支持该语言的 <推荐引擎>？」；
   选「保留当前引擎」则语言退回该引擎支持的第一项。（窗口未显示、初始化、程序化同步时不弹）
2. **点「开始处理」时**：开跑前守卫弹窗，按钮为「切换到 <推荐引擎>」／「仍用当前引擎」／「取消」；
   选「取消」则本次不启动。切换后自动保持原语言选中，`use_gpu` 等参数一并重算。

### 3.4 语言下拉到底起什么作用（按引擎，重要澄清）

> 常见疑问：**V6 引擎里选法文 / 德文 / 西班牙文，出来的结果好像一样 —— 语言选择是不是只是"声明"，没有实际影响？**
> **答：在 v6 引擎内，多数语种确实共用同一份模型与字典，语言不改变识别结果；只有少数文字会真正切换模型。** 下表是各引擎的真实行为（依据 `ppocr_v6_server.py` 的 `_V6_LANGS` 分流与实测字典覆盖）。

| 引擎 | 语言是否改变识别结果 | 真实行为 |
|---|---|---|
| **PP-OCRv6** (`umi_plugin_v6`) | **多数否 / 少数是** | 「中 / 英 / 日 + 46 种拉丁语系」→ **共用同一份 PP-OCRv6 模型 + 同一份通用字典**，选哪个语种结果都一样，语言只表示「文档里可能出现哪些文字」；<br>「韩 / 西里尔（俄等）/ 阿拉伯 / 天城 / 泰 / 泰卢固 / 泰米尔 / 希腊」→ **自动改用 PP-OCRv5 官方分语种模型**（此时语言真正生效，强制 CPU，约 3 秒/页） |
| **PP-OCRv5 (Paddle CPU)** (`win7_v5`) | **是（★ 分语种模型 + 分语种字典）** | 模型按语言路由到官方分语种 rec 模型，**每个语系配自己的字典**：`config_universal.txt`→`PP-OCRv5_server_rec_infer`+`ppocr_keys_v1.txt`；`config_latin.txt`/`config_arabic.txt`/`config_korean.txt`/`config_eslav.txt`/`config_cyrillic.txt`/`config_devanagari.txt`/`config_th.txt`/`config_el.txt`/`config_te.txt`/`config_ta.txt`→各自 `*_PP-OCRv5_mobile_rec_infer` + 该模型自带 `ppocr_keys.txt`（33 组映射见第四节） |
| **PP-OCR (ncnn Vulkan)** (`ncnn_vulkan`) | **否** | 字典由**所选模型**决定（v3→`ppocr_keys_v1`；v6→`ppocr_keys_v6`；其余 v5/v4 模型→`ppocr_keys_v5`），语言参数只被打印进日志，**不参与识别** |
| **EasyOCR** (`easyocr_universal`) | **是** | 语言决定加载哪套识别模型（仅 英/法/意/西） |

> ⚠ **最容易踩的混淆 —— 两个「v5」不是一回事**：
> - **`win7_v5` = PP-OCRv5 (Paddle CPU) 引擎** → **分语种模型 + 分语种字典**，语言**真正生效**（阿拉伯文用阿拉伯模型、韩文用韩文模型…）；
> - **ncnn 引擎里可选到的「PP-OCRv5 模型」** → 无论选什么语言都用**同一份 `ppocr_keys_v5.txt`**，语言**不生效**。
>
> 判断口诀：**看「引擎」，不是看「模型名」**。「Paddle」= 分语种；「ncnn」= 单份字典。

**「两个 v5」的文件级证据**（可自行核对）：

| V5 形态 | 位置 | 字典个数 | 证据 |
|---|---|---|---|
| PP-OCRv5 (Paddle CPU) 引擎 | `ppocr_v5/models/config_*.txt` | **11 份**（arabic / devanagari / th / el / te / ta / korean / eslav / cyrillic / latin / universal），各自 `rec_char_dict_path` 指向**本模型目录下的** `ppocr_keys.txt` | `ppocr_v5/models/*_PP-OCRv5_mobile_rec_infer/ppocr_keys.txt` |
| ncnn 的 PP-OCRv5 **模型** | `ncnn/PPOCR-ncnn-Vulkan/models/` | **1 份** `ppocr_keys_v5.txt`（`PP_OCRv5_mobile_rec` 与 `PP_OCRv5_server_rec` 共用） | 整个 ncnn 目录只有 `ppocr_keys_v1/v5/v6/v6_tiny` 四个字典文件；选字典只看模型版本字符串（`"v3"`→v1、`"v6"`→v6、其余→v5） |

- 判定依据：`_V6_LANGS = {ch, chinese_cht, japan} ∪ 46 种拉丁语系`。**落在这个集合里 → 同一份 v6 模型 + 同一份字典**。
- 这也是为什么简单模式里把「拉丁语系（法德西意等）」合并成 **1 组**：它们在主力引擎下走的是**同一套**识别，拆开列没有意义。
- 界面上**不常驻**这段说明（避免占版面），改放在「语言下拉」的**悬停 tooltip** 里；精确规则以本文为准。
- 另外：专业模式「模式」下拉默认值是 **自动(推荐)**，语义为 **检测到独显就用 GPU、无独显自动回退 CPU** —— 有独显时默认实际就跑 GPU。也可单独手动指定「GPU模式 / CPU模式」（选过的值会记住）。
- **重要**：语言选择的真正价值在于"**提前把引擎切到能认这些文字的那个**"——见第二节路径 A/B。选错语言的后果不是"识别风格不同"，而是**换了不认识的字典 → 整页乱码**。

## 四、引擎参数构建（`build_engine_params`）

### `umi_plugin_v6` 的自动回退（`ppocr_v6_server.py`）

- `lang ∈ _V6_LANGS` 或含 `&`（如 `multilang_v6`）→ 用 **PP-OCRv6** det+rec 模型（本地缓存优先）
- 否则 → 走 **PP-OCRv5** 分支：`ocr_version="PP-OCRv5"`，由 PaddleX 按 lang 自动选分语种模型，并**强制 CPU EP**
  - 强制 CPU 的原因：v5 分语种模型在 ORT CUDA EP 下会 `RUNTIME_EXCEPTION`（崩在 `Conv`，与显存大小无关），CPU EP 实测完全正常
- 已缓存的 11 套 v5 分语种模型：arabic / devanagari / th / el / te / ta / korean / eslav / cyrillic / latin / en

## 五、Lite 轻量版规则（差异）

Lite 只有 **ncnn 引擎**（Vulkan / CPU 两种模式），因此：

| 维度 | 规则 |
|---|---|
| 语言（简单模式） | **14 项**单选下拉：前 6 项为轻量版支持（中文／英文／日文／拉丁语系／希腊文／多语言混排），中间一条**分隔行**，其后 7 项（韩／西里尔／阿拉伯／天城／泰／泰卢固／泰米尔）**灰显不可选**并在项名后标注"（需专业版）"；✅ 支持 / ❌ 需专业版 两类范围写在**下拉悬停提示**里（界面不常驻大段文字） |
| "多语言混排" | **属于支持项**（v6 通用字典覆盖中/英/日/拉丁），不再标 ⚠、"需专业版" |
| 语言（专业模式） | 完整 17 项；韩文/俄文灰显（显示名带「（需专业版）」后缀）+ 悬浮提示；持久化兜底（上次选的不支持项重置为中文） |
| 引擎 | 固定 ncnn；只选 **GPU 模式（Vulkan）** 或 **CPU 模式**（`use_gpu=False`，与 Vulkan 是同一二进制） |
| 显卡下拉 | 5 项：独显 ≥12GB ／ 独显 ≤8GB ／ 仅有核显 ／ 纯CPU ／ **🤖 帮我选择（自动检测）** |
| 边长 / 渲染 | 与 Pro 同一套规则：速度·标准 → **2240 + 2x**；精度优先 → 大显存(档0)／纯CPU(档3) **2560**、小显存(档1)／核显(档2) **2240**；**3x 仅「古籍 + 精度优先 + 大显存或纯CPU」** |
| 批处理数 | 简单模式不干预（沿用专业模式 / 配置值，默认 12） |
| 参数 | 精度档 → 模型(v6 small/medium) + FP16/FP32；文档类型 → 竖排 / 方向纠正 |
