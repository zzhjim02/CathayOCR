# CathayOCR Pro 引擎与参数选择规则（v1.3.0）

> 本文是引擎/参数自动选择规则的**单一事实来源**，与代码逐条对应（`CathayOCR-Pro/umi_ocr_pdf_processor_ui.py`、
> `ppocr_v6/ppocr_v6_server.py`）。简单模式全自动；专业模式全手动 + 开跑前守卫。

---

## 一、简单模式：4 个问题 → 全部参数

### Q1 文档类型 → 竖排检测 / 方向纠正

| 选择 | 竖排检测 | 方向纠正 |
|---|---|---|
| 普通文档（横排印刷体） | 关 | 关 |
| 古籍竖排（繁体/竖排/复杂排版） | **开** | 关 |
| 扫描件/照片（可能方向不正） | 关 | **开** |

> 文档类型**不再决定边长与渲染倍率**——这两项统一由「精度档 + 显存档」决定（见 Q3）。
> 渲染倍率只有一种情况会用到 3x：**古籍 + 精度优先 + 大显存（或纯CPU）**。

### Q2 精度与速度 → 模型参数

| 选择 | 模型 | 批处理数 | 浮点精度 | 对齐 shrink |
|---|---|---|---|---|
| 速度优先 | v6 small | **16** | FP16 | 关 |
| 标准平衡（推荐） | v6 medium | **16** | FP32 | 关 |
| 精度优先 | v6 medium | **16** | FP32 | **开** |

> **批处理数与精度档无关**，三档统一 **16**（常量 `_SIMPLE_REC_BATCH`），不再随档变化。

### Q3 显卡 → 引擎 + 运行模式 + 边长 + 渲染倍率

下拉 6 档：`0` NVIDIA ≥12GB ／ `1` NVIDIA ≤8GB ／ `2` AMD·Intel ≥12GB ／ `3` AMD·Intel ≤8GB ／ `4` 核显·纯CPU ／ `5` 自动检测

**引擎 / 运行模式**

| 档位 | 运行模式 | 普通语言引擎 |
|---|---|---|
| 0 NVIDIA ≥12GB | auto | PP-OCRv6 (ONNX CUDA) |
| 1 NVIDIA ≤8GB | auto | PP-OCR ncnn Vulkan |
| 2 AMD/Intel ≥12GB | auto | PP-OCR ncnn Vulkan |
| 3 AMD/Intel ≤8GB | auto | PP-OCR ncnn Vulkan |
| 4 核显·纯CPU | **cpu** | PP-OCR ncnn CPU |

双实例：非纯 CPU 档默认**开**；纯 CPU 档自动**关**（无增益）。

**边长与渲染倍率（定稿）**

| 速度档 / 显存档 | 边长 | 渲染倍率 |
|---|---|---|
| 速度优先 | **2240**（一律） | **2x** |
| 标准平衡 | **2240**（一律） | **2x** |
| 精度优先 · **大显存**（档 0/2）或纯CPU（档 4） | **2560** | 古籍 → **3x**；其余 → 2x |
| 精度优先 · **小显存**（档 1/3） | **2240** | **2x** |

- 大显存档 = `{0, 2, 4}`（NVIDIA ≥12GB ／ AMD·Intel ≥12GB ／ 纯CPU）；小显存档 = `{1, 3}`
- 渲染 **3x 的唯一触发条件**：古籍竖排 + 精度优先 + 大显存（或纯CPU）。其余一律 2x，**不再有 X3**
- 自动检测（档 5）落点：`nvidia-smi` 显存 ≥11000 MiB → 0，否则 → 1；无 N 卡但有 Vulkan 独显 → **3**（Vulkan 探测读不到显存，AMD/Intel 一律保守按小显存档）；只有核显 / 探测失败 → 4

> ⚠ **CUDA 能力与显存大小无关**：8GB 的 N 卡一样能跑 CUDA。档位只决定"**普通语言用哪个引擎**"以及**精度优先时的边长**。

### Q4 文档语言（13 组多选勾选）→ 引擎决策

| # | 勾选项 | 代码 | ⚠ |
|---|---|---|---|
| 1 | 中文 | ch | |
| 2 | 英文 | en | |
| 3 | 日文 | japan | |
| 4 | 韩文 | korean | ⚠ |
| 5 | 西里尔文系 (俄/乌/保等) | ru | ⚠ |
| 6 | 拉丁语系 (法德西意等) | fr | |
| 7 | 阿拉伯文系 (阿/波/维/乌等) | ar | ⚠ |
| 8 | 天城文系 (印地/马拉地等) | hi | ⚠ |
| 9 | 泰文 | th | ⚠ |
| 10 | 希腊文 | el | |
| 11 | 泰卢固文 | te | ⚠ |
| 12 | 泰米尔文 | ta | ⚠ |
| 13 | 多语言混排 (中英日及拉丁系) | multilang_v6 | |

> **勾选语言只用于"选哪个引擎/模型"，不改变识别字典**。主力引擎本就是通用字典，勾不勾都认；
> 勾选的真正作用是：一旦出现 ⚠ 组，提前把引擎切到能认它的那个，避免乱码。
> ⚠ 组共 7 个（韩文/西里尔/阿拉伯字母/天城文/泰/泰卢固/泰米尔）。**希腊文不是 ⚠**——实测 ncnn 字典含 76 个希腊字符，可直接识别。
> **多语言混排不含韩/俄**：混排中以中/英/日/拉丁为主，主力引擎覆盖；若文档里还夹着韩/俄，**请把对应 ⚠ 组也勾上**。

## 二、引擎决策（两条路径）

设 `nvidia = 档位 ∈ {0, 1}`（任意 NVIDIA 卡都具备 CUDA）。

### 路径 A：普通路径（未勾选任何 ⚠ 组）

| 档位 | 引擎 |
|---|---|
| 0 NVIDIA ≥12GB | **PP-OCRv6 (ONNX CUDA)** — 用 CUDA 换最高精度 |
| 1 NVIDIA ≤8GB | **PP-OCR ncnn Vulkan** — 省显存、可双实例，批处理更快 |
| 2 AMD/Intel ≥12GB | **PP-OCR ncnn Vulkan** |
| 3 AMD/Intel ≤8GB | **PP-OCR ncnn Vulkan** |
| 4 核显/纯CPU | **PP-OCR ncnn CPU** |

> 为什么 ≤8GB 走 Vulkan：显存占用低、双实例加速，实测约 2.2 页/秒（CUDA 约 1.1 页/秒）。
> AMD/Intel 卡没有 CUDA，**一律走 Vulkan**（显示分档只影响精度优先时的边长）。

### 路径 B：⚠ 专用路径（勾选了任一 ⚠ 组）

| 档位 | 引擎 | 说明 |
|---|---|---|
| 0 / 1（任意 NVIDIA） | **PP-OCRv6 (ONNX CUDA)** | 引擎**自动回退官方 PP-OCRv5 分语种模型**；分语种模型目前走 CPU 推理，实测约 3 秒/页 |
| 2 / 3 / 4（非 NVIDIA） | **PP-OCRv5 (Paddle CPU)** | 纯 CPU 备选，内置 11 套官方分语种模型 |

> 这 7 类文字在 ncnn 通用字典里**实测 0 字符覆盖**，留在 ncnn 必乱码，所以必须切引擎。
> "NVIDIA → v6 引擎"只表示**选用哪个引擎**（v5 分语种模型只有 v6 引擎能调），不代表独占 GPU 加速。

### 降级链（引擎缺失时）

⚠ 路径下若 v6 引擎不可用 → `win7_v5` → `ncnn_vulkan` → `ncnn_cpu`（取第一个可用）。

配置摘要栏会明示：`⚠ 已切换：勾选⚠语言 → PP-OCRv6 引擎自动回退分语种模型`（或 `→ PP-OCRv5 (Paddle CPU) 备选引擎`）。

## 三、专业模式

引擎、设备、模型、语言全部自由组合。**唯一自动干预**是开跑前守卫：

> ncnn 引擎（`ncnn_cpu` / `ncnn_vulkan`）+ 语言属于「通用字典 0 覆盖」的 33 项 →
> 弹窗提示"该文字不在 ncnn 通用字典中…仍要继续吗？"，默认选 **否**。

## 四、引擎参数构建（`build_engine_params`）

| 引擎 | 入口类型 | 关键参数 |
|---|---|---|
| `umi_plugin_v6` | 管道 JSON | `config_path=models/config_{medium\|small}.txt`、`lang`、`model_size`、`rec_batch_num`、`shrink_poly_ratio`、`blank_page_strategy=skip` |
| `ncnn_vulkan` | TCP 持久 | `max_side_len`、`enable_cls`、`num_threads`、`enable_fp16`、`det_thres=0.5`、`unclip_ratio=1.58`、`use_gpu`、`lang`、`gpu_device` |
| `ncnn_cpu` | 子进程单次 | 同 ncnn Vulkan，但无 `use_gpu` / `gpu_device` |
| `win7_v5` | 管道 JSON | `enable_mkldnn=True`、`cpu_threads`、`config_path`（按 lang 路由） |
| `win7_classic` | 管道 JSON | `config_path=models/config_chinese.txt` |

### `win7_v5` 的 lang → config 路由（33 组映射）

| 文字系 | 语言代码 | config |
|---|---|---|
| 阿拉伯字母系 | ar fa ug ur ps sd ks bal | `config_arabic.txt` |
| 天城文系 | hi mr ne sa bh mai kok | `config_devanagari.txt` |
| 泰 / 希腊 / 泰卢固 / 泰米尔 | th / el / te / ta | `config_th.txt` / `config_el.txt` / `config_te.txt` / `config_ta.txt` |
| 韩文 | korean | `config_korean.txt` |
| 东斯拉夫 | ru uk be | `config_eslav.txt` |
| 其余西里尔 | bg mk mn kk ky tg tt ba cv rs_cyrillic | `config_cyrillic.txt` |
| 拉丁语系（44 种） | fr de es it pt nl ro ca gl da sv no fi is pl cs sk hu hr sl bs rs_latin sq ga cy et lt lv mt la pi af az uz ku eu oc vi id ms tl sw mi tr | `config_latin.txt` |
| 中/英/日及其他 | ch en japan … | `config_universal.txt` |

### `umi_plugin_v6` 的自动回退（`ppocr_v6_server.py`）

- `lang ∈ _V6_LANGS` 或含 `&`（如 `multilang_v6`）→ 用 **PP-OCRv6** det+rec 模型（本地缓存优先）
- 否则 → 走 **PP-OCRv5** 分支：`ocr_version="PP-OCRv5"`，由 PaddleX 按 lang 自动选分语种模型，并**强制 CPU EP**
  - 强制 CPU 的原因：v5 分语种模型在 ORT CUDA EP 下会 `RUNTIME_EXCEPTION`（崩在 `Conv`，与显存大小无关），CPU EP 实测完全正常
- 已缓存的 11 套 v5 分语种模型：arabic / devanagari / th / el / te / ta / korean / eslav / cyrillic / latin / en

## 五、Lite 轻量版规则（差异）

Lite 只有 **ncnn 引擎**（Vulkan / CPU 两种模式），因此：

| 维度 | 规则 |
|---|---|
| 语言（简单模式） | **14 项**单选下拉：前 6 项为轻量版支持（中文／英文／日文／拉丁语系／希腊文／多语言混排），中间一条**分隔行**，其后 7 项（韩／西里尔／阿拉伯／天城／泰／泰卢固／泰米尔）**灰显不可选**并提示"需专业版"；下拉框下方常驻一行**支持范围说明**（✅ 支持 / ❌ 需专业版 两类文字写清） |
| "多语言混排" | **属于支持项**（v6 通用字典覆盖中/英/日/拉丁），不再标 ⚠、"需专业版" |
| 语言（专业模式） | 完整 16 项；韩文/俄文灰显 + 悬浮提示；持久化兜底（上次选的不支持项重置为中文） |
| 引擎 | 固定 ncnn；只选 **GPU 模式（Vulkan）** 或 **CPU 模式（ncnn 原生）**；双实例仅 GPU 模式有效 |
| 显卡下拉 | 5 项：独显 ≥12GB ／ 独显 ≤8GB ／ 仅有核显 ／ 纯CPU ／ **🤖 帮我选择（自动检测）** |
| 边长 / 渲染 | 与 Pro 同一套规则：速度·标准 → **2240 + 2x**；精度优先 → 大显存(档0)／纯CPU(档3) **2560**、小显存(档1)／核显(档2) **2240**；**3x 仅「古籍 + 精度优先 + 大显存或纯CPU」** |
| 批处理数 | 简单模式不干预（沿用专业模式 / 配置值，默认 12） |
| 参数 | 精度档 → 模型(v6 small/medium) + FP16/FP32；文档类型 → 竖排 / 方向纠正 |

## 六、实测数据（本机：AMD Ryzen 7 8845H + RTX 5060 8GB）

| 项目 | 结果 |
|---|---|
| 中文主路径（v6 medium，156 页书） | init 7.9s，49 行输出，逐字与旧版一致（零退化） |
| ⚠ 语种（韩/俄/阿/泰） | 逐字正确，~3 秒/页（CPU 推理） |
| ncnn Vulkan 双实例 | ~2.2 页/秒 |
| v6 CUDA 单实例 | ~1.1 页/秒 |
| 新旧 Lite 引擎 | exe + 34 个模型文件 md5 逐一相同 |

> **已知特性**：阿拉伯字母系（阿/波/维/乌）输出为镜像序（PaddleOCR 官方模型的字符顺序特性），字符识别正确，可自行反转文本顺序。
