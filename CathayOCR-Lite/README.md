# CathayOCR Lite (轻量版) v1.3.5

基于 ncnn Vulkan 的便携式 PDF OCR 工具。CathayOCR 专业版的轻量分支。

> 🟢 **v1.2.4 = 稳定版**（久经考验，求稳就用它）；🟡 **v1.3.5 = 测试版**（就是本版）。
> 两版可以放在同一个文件夹里**并存**，互不影响。

---

## 🌟 这版好在哪？（不懂技术也能看）

新版不是"把数字改大"，它实实在在解决了四类问题——**哪怕你完全不懂 OCR，也能直接感受到差别。**

### ① 🎨 界面更好看、更好用了

- **迷你窗口**：处理的时候，主窗口和日志窗口一起收成屏幕右下角的一张**小卡片**，上面有两条进度（"本文件：第 3 / 12 页" + "总进度：已处理 12 / 40"）。卡片能拖、能置顶，**跑完自动还原**——你可以边干别的边等它跑。
- **运行日志落盘**：处理过程按天写进 `logs\` 文件夹，出问题随时能翻出来看。
- **列表顺手**：`Ctrl / Shift` 多选、`Delete` 批量移除、一键剔除已完成；跑完的条目自动打绿 ✔。
- **不怕手滑**：开始处理后就锁住配置，改不动。

### ② 🧠 选模型、选参数更科学了

老版把"用哪个模型、图像边长多少、批处理几个"这些全摊在你面前，让你自己猜——猜错了就是又慢又差。

新版改成：**你只回答几个问题，剩下它来定。**

- 勾上「🎯 简单模式」，回答 **文档类型 → 要速度还是要精度 → 什么显卡 → 什么语言**，它自动配好模型与全部参数；
- 显卡那一项即使你选「🤖 我不知道」，它也会**自己去检测**；
- 图像边长按「速度 / 标准 / 精度 × 你的显存大小」**自动推荐**，不再是一串要你自己琢磨的数字。

### ③ 🎛️ 参数更贴合实际需要

同一套参数，在 8 GB 显存和 24 GB 显存上、在"随便翻翻"和"要精确引用"上，本来就该不一样。

新版把**显存大小和文档类型**都考虑了进去：给出的就是"你这个配置上的稳妥值"。想细调，专业模式里照样全都能改。

### ④ 🌍 语言这块，从"看着能用"变成"真能用"

- **希腊文、越南文**等语言：老版选了**其实不生效**（语言没真正传给引擎），现在**真的会按你选的语种识别**；
- **修了一个"拿错字典"的老毛病**：以前有两个模型会拿到和它自身不匹配的字典（对不上号），结果就是**整页乱码、甚至算到卡死**——现在按实际使用的模型取字典，不会再错配；
- **不认识的语言会明说**：韩文、俄文等西里尔文系、阿拉伯文系、天城文系、泰文等，Lite 的字典确实认不了，下拉里会**灰掉并标注「需专业版」**，不会再让你选了以后白跑一趟（要这些请用 **CathayOCR 专业版**）。

### 一句话对照

| 你关心什么 | 老版 | 新版 v1.3.5 |
|:---|:---|:---|
| 界面 | 能用 | 好看好用（迷你窗口 / 日志可查 / 批量操作） |
| 选模型、调参数 | 自己猜 | 回答几个问题，它来定 |
| 希腊文、越南文 | 选了没反应 | 真的按语种识别 |
| 韩文、俄文等 Lite 认不了的 | 选了白跑一趟 | 直接灰掉 + 标注「需专业版」 |

> 💡 **要不要升级？** 求稳可以继续用 v1.2.4 稳定版；想解决上面这些问题、愿意帮忙测一测，就用本版 v1.3.5。

✨ **v1.3.1 更新内容**

> 本版以**稳定运行的 v1.2.4 引擎链路为基线**（引擎调用、看门狗、双实例并行、超时策略、临时文件、请求派发方式**全部保持 v1.2.4 原样**），只补三类与引擎运行时行为无关的东西：**语言与字典路由修复**、**出错保护层**、**界面与可维护性增强**。

1. **修复「模型 ↔ 字典错配」Bug（重要）**
   - 原逻辑按**模型名字符串**猜字典（含 `v3` → v1 字典、含 `v6` → v6 字典、其余 → v5 字典），导致两个模型选错字典：
     - `PP_OCRv4_mobile`：名字既不含 `v3` 也不含 `v6` → 落进兜底拿到 **v5 字典（18384 行）**，而该模型只输出 **6625** 类
     - `PP_OCRv6_tiny`：名字含 `v6` → 拿到 **v6 字典（18709 行）**，而该模型只输出 **6906** 类
   - 后果：模型输出维度与字典行数对不上（相差一万多行），识别结果轻则整页乱码、重则引擎算到一半卡死并触发超时
   - 修复：改为**按实际选中的模型**路由字典，且 `v6_tiny` 优先于 `v6` 判断（四个模型的正确字典：v3/v4→`ppocr_keys_v1.txt`、v5→`ppocr_keys_v5.txt`、v6→`ppocr_keys_v6.txt`、v6_tiny→`ppocr_keys_v6_tiny.txt`）
   - 附带修好：`ppocr_keys_v6_tiny.txt` 这份字典在旧版中**从未被任何模型选中过**

2. **语言下拉大扩充，并按「当前字典的真实能力」如实标注**
   - 简单模式语言项：6 → 14 项（含一条「以下文字需专业版」分隔行）
   - 专业模式语言项：15 → 19 项（含一条说明行 + 一条分隔行）
   - 下拉中**灰色不可选**的条目 = 当前 Lite 的 ncnn 字典确实不覆盖该文字系（韩文/西里尔/阿拉伯/天城/泰/泰卢固/泰米尔）
   - 越南文标注「部分支持·可能缺重音」（四份字典对越南文声调的覆盖都不完整）
   - 语言列表会**随所选模型动态刷新**：不同模型用不同字典，覆盖能力不同

3. **修复三处「选了语言却不生效 / 悄悄跑错语言」**
   - **语言表如实标注**了各语言在轻量版的支持状态（旧版把不支持的也一并列出、无任何提示）
   - **字典跟随实际选中模型**（见第 1 条）
   - **简单模式 ↔ 专业模式的语言同步改为按「语言代码」匹配**：旧版按**显示文本**匹配，一旦两边文案不同（如「Ελληνικά (希腊文)」对不上「希腊文」）就匹配失败，**默默回退到第 0 项用中文跑**，用户完全看不出来；现在按代码同步，不会再悄悄跑错语言

4. **出错保护层：完整性闸门 + 三级恢复（宁可重跑，也绝不悄悄少页）**
   - 旧版 `write_results` 对失败页是 `continue` —— **无声丢掉**，结果少了几页也看不出来
   - 现在：`_RESULT_OK_CODES = (100, 101)`（`101` = 引擎明确回复本页无文字，算**有结论**）+ 完整性检查
   - 三级恢复：**某页失败 → 重试该页 1 次**（超时则先把两个引擎一起重启）→ 仍失败 → **整份文件重处理 1 次** → 仍失败 → 跳过该文件并在源文件目录写 **`{文件名}_OCR未完成警告.txt`**，同时报错
   - 用户主动取消时提示「已取消」，不再误报「批量处理完成」

5. **界面与可维护性增强**
   - 🪟 **迷你窗口模式**：处理中把**主窗口与日志窗口一起**收成右下角 420×146 小卡片（文件名 + 已处理/总数 + 进度条），可拖动、可置顶，处理完自动还原
   - 📝 **运行日志落盘**：全部输出同时写入 `logs\CathayOCR-Lite-日期.log`，出问题有据可查
   - 🧹 **按路径精确清理**：启动时只结束「exe 路径在本软件目录内」的引擎进程，**不再按进程名全系统强杀**（不会误伤其它位置正在运行的同类程序）
   - 📋 **列表管理**：`Ctrl/Shift` 多选 + **Delete** 批量移除、「一键剔除已完成」、完成项打绿色 **✔**
   - 📂 **输出目录说明**：默认留空 = **输出到每个 PDF 自己所在的文件夹**；不再回填上次路径，界面加灰字说明
   - 🤖 **引擎/参数推荐**：显卡下拉新增「🤖 自动检测」；边长按「速度/标准/精度 × 显存大小」自动推荐；**处理中锁定全部配置**


## TXT 文本层写回工具

> 位置：`TXT写回工具\` 目录
> 双击 `启动工具.bat` 即可运行

### 它是什么？

一个**批量修复「双层 PDF 无法搜索」问题的独立小工具**。

很多古籍 PDF（网上下载或旧工具生成）带有**错误/无法搜索的隐藏文本层**——用 Chrome/Edge 打开时 Ctrl+F 搜不到字，但同名的 `_result.txt` / `_PD6AIFOCR.txt` 里却有完整 OCR 文字。

本工具把 TXT 里的识别结果**按页码重新写回 PDF**，替换掉错误的旧文字层，让 PDF 重新可搜索、可复制。

### 核心能力

- **按页码对应**：TXT「第 N 页」的内容写入 PDF 第 N 页，不依赖图像坐标
- **竖排古籍风格**：每页文字从右上角起，每行一列，列从右到左（rotate=270），符合古籍版式
- **透明文字层**：不影响看图，可正常复制/搜索
- **彻底清除旧层**：删除内容流中全部旧文字（含残留 TD 块），图像层无损
- **多核并行**：默认 4 线程同时处理多个文件，可调 1~16，处理 400+ 文件大幅提速
- **递归扫描**：选择任意父目录，自动扫描所有子目录配对
- **保留原件**：输出 `XXX_..._fixed.pdf`，不覆盖原文件

### 自动识别的文件配对

| TXT | PDF | 来源 |
|---|---|---|
| `XXX_result.txt` | `XXX_layered.pdf` | CathayOCR Lite 输出 |
| `XXX_PD6AIFOCR.txt` | `XXX_PD6AIFOCR_opt.pdf` | FOCR 工具输出 |
| `XXX_PD6AIFOCR.txt` | `XXX_PD6AIFOCR.pdf` | FOCR 无 _opt 变体（如北洋政府公报） |

其它后缀（`_FOCR_opt.txt`、`_【繁转简】` 等）一律忽略。

## ⚠️ GPU 卡死 / 跑出大量空白？先看这里（Windows TDR 超时）

**现象**：进度条还在走、程序也不报错，但导出的文件大量空白；或日志里反复出现 `[自动恢复] 重建引擎`。

**原因**：**不是软件 Bug**。Windows 有一条「GPU 超时看门狗」（**TDR**）规则——单个 GPU 任务超过默认
**2 秒**没算完，系统就判定显卡卡死，**强制重置显卡驱动**。驱动一重置，OCR 引擎手里的显卡设备就
永久作废（`VK_ERROR_DEVICE_LOST`），但进程不退出、端口还在，于是**每页都算不出来**（表现为空白）。

**两步解决（建议都做）：**

**① 放宽 TDR 超时（治本，一次搞定）** —— 本目录已放好两个注册表文件，**双击**即可：

| 文件 | 作用 |
|---|---|
| `GPU卡死修复_调大TDR超时_需重启.reg` | 把 2 秒放宽到 **8 秒**：双击 → 弹窗点「是」→ **重启电脑**生效 |
| `GPU卡死修复_还原TDR超时_需重启.reg` | 想还原：双击它 + 重启，恢复 Windows 默认 |

> 唯一副作用：万一显卡真的挂了，桌面最多卡 8 秒才恢复（原来 2 秒）。

**② 把「精度」改成 FP16（降低单次 GPU 负载）** —— 专业模式 →「精度」下拉选 **`FP16 (快速)`**。
单次 GPU 计算量大幅下降，更难撞上超时线，对识别结果影响极小。（**AMD 核显请保持 FP32**。）

**软件自身的兜底（v1.3.4 起）**：即使真撞上，程序会探测到引擎已废 → **自动重建引擎 → 重跑本页**，
**绝不把「算不出来」当成「这页空白」交付**。日志里 `[自动恢复]` 开头的行 = 保护层正在工作，
**无需干预**。想查引擎的原话，看 `ncnn\PPOCR-ncnn-Vulkan\engine_<端口>_stderr.log`。

## 使用方法

### 方式一：双击启动（推荐，最简单）

1. 进入 `CathayOCR-Lite\` 目录

3. 🎯 简单模式：选择语言 → 点运行

## 故障排除

| 问题 | 原因 | 解决 |
|------|------|------|
| GPU 模式黑屏/崩溃 | 显卡驱动过旧 | 更新显卡驱动 |
| AMD 核显高频崩溃 | FP16 加速不稳定 | 切换到 FP32 精度 |
| 自动模式选了 CPU | 未检测到合适独显 | 手动切换为「GPU 模式」 |
| 无法启动 | 安全软件拦截 | 加入信任区或命令行运行查看错误 |
| 进度卡住不动 | 子进程异常 | 检查任务管理器有无残留 ppocr 进程，重启程序 |
| 选了韩文/俄文等没效果 | 轻量版 ncnn 字典不含该文字系 | 下拉中已灰显，请改用专业版 |
| 语言下拉变成灰色不可选 | 当前所选模型的字典不覆盖该语言 | 换用覆盖更广的模型（如 v6 Medium）或改用专业版 |
| 竖排古籍顺序仍乱 | 未勾选「竖排识别」 | 勾选「OCR 选项」中的「竖排识别」后重新运行 |
| 竖排 PDF 搜不到文字 | 竖排文字横排写入超界 | 勾选「竖排识别」后重新运行 |
| 导出 PDF 搜不到文字 | OCR 像素坐标未换算 | 重新运行一次即可 |
| 看到「重新处理第 N 页 / 整份文件重跑」日志 | 保护层检测到失败页（正常行为） | 无需干预；若最终报错，同目录会有 `_OCR未完成警告.txt`，按提示重跑该文件 |
| 想查某次运行到底发生了什么 | — | 打开 `logs\CathayOCR-Lite-日期.log` |
| TXT 有字但 PDF 搜不到 | 旧文字层错误/超界 | 用附赠的 TXT 文本层写回工具修复 |
| **GPU 模式跑一阵后大量空白 / 日志反复刷「[自动恢复] 重建引擎」** | Windows TDR 默认只给 GPU **2 秒**，超时就把显卡驱动重置了 | ① 双击本目录 `GPU卡死修复_调大TDR超时_需重启.reg` 后**重启**；② 专业模式「精度」改 **FP16**（见卷首专章） |
