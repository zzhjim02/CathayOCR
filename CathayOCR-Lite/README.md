# CathayOCR Lite (轻量版) v1.2.3

基于 ncnn Vulkan 的便携式 PDF OCR 工具。CathayOCR 专业版的轻量分支。

## 特性亮点

🚀 **单一引擎，一键启动**
- 仅保留 ncnn Vulkan 引擎，无需选择纠结
- GPU 模式（Vulkan 加速）/ CPU 模式（原生 ncnn，不初始化 Vulkan）
- 支持任意品牌显卡：NVIDIA / AMD / Intel 均可
- 支持 PP-OCR 多版本模型（v3 ~ v6）

📦 **极致便携，U 盘即用**
- 体积仅 ~1.4 GB，原始版 9 GB 的 1/6
- 自带便携 Python 环境，无需任何安装

🌍 **多语言支持**
- 中文（繁简体自动识别）、English、Français、Deutsch、日本語、한국어
- Español、Italiano、Português、Pусский、Tiếng Việt 等

📄 **PDF OCR 专业功能**
- GPU 双实例并行（提升 30~50%）
- 古籍/竖排/复杂排版支持
- 拖放文件处理，批量输出

🛠️ **附赠 TXT 文本层写回工具**（`TXT写回工具\` 目录）
- 批量把 OCR 结果 TXT 写回 PDF，替换无法搜索的旧文字层
- 竖排古籍风格排版、透明可搜索文字、多核并行加速
- 详见下方「TXT 文本层写回工具」章节

✨ **v1.2.3 更新内容**

1. **修复「竖排识别」无效的 Bug（重要）**
   - 原「竖排文字」选项只是一个**无效开关**：勾选后并不会真正改变识别结果的输出顺序（参数沿 UI → 工作线程 → OCR 客户端层层传递，却从未被引擎使用）
   - 真实影响：竖排古籍的 OCR 结果始终按横排顺序输出，顺序混乱、无法直接阅读
   - 现在：勾选「竖排识别」后，识别结果会按竖排阅读顺序重新排列（**从右→左、列内上→下**），纯 CPU 后处理，几乎零耗时
   - 来龙去脉：此前有用户反馈"竖排识别顺序混乱"，当时大家未察觉是「竖排识别根本没生效」的 Bug，误以为是识别模型能力不足，一度计划引入 PaddleOCR v1.6 来解决问题。本次排查发现真实原因后，仅需修复参数链路即可，无需更换模型

2. **新增「覆盖旧OCR」功能**
   - 勾选后，导出双层 PDF 时**物理删除原 PDF 中的全部旧文字层**，只叠加本次新识别出的文字
   - 扫描图像层与矢量图形 **100% 无损保留**（300% 缩放依然清晰）
   - 适用场景：PDF 中已带效果较差的旧 OCR 文字层，希望用本次识别结果整体替换
   - 未勾选时保持原有行为（新旧文字层并存），完全向后兼容

3. **修复竖排文字写不进 PDF / 搜索不到的问题（重要）**
   - 此前竖排古籍 OCR 的检测框是「高>宽」的竖条框，但导出时文字仍按**横排**写入（rotate=0），整句横向展开后超出页面右边界，导致超出页面的文字被 PDF 查看器/提取器**裁剪丢弃** → PDF 里搜不到、甚至缺字（TXT 完整但 PDF 搜不到）
   - 现在：检测框为竖条框（高>宽）时，文字以 **rotate=270 从框顶向下竖排写入**，整句完整落在页面内，可正常搜索
   - 该行为与「竖排识别」选项联动：**勾选「竖排识别」** 才按竖排方式写入；不勾选则保持旧版横排行为
   - 横排文档（宽>高横条框）走原逻辑，完全不受影响

4. **新增 TXT 文本层写回工具 v1.1（附赠）**
   - 详见下方章节

## TXT 文本层写回工具

> 位置：`D:\我的软件创作库\Cathay OCR Lite\TXT写回工具\`
> 双击 `启动工具.bat` 即可运行

### 它是什么？

一个**批量修复「双层 PDF 无法搜索」问题的独立小工具**。

很多古籍 PDF（网上下载或旧工具生成）带有**错误/无法搜索的隐藏文本层**——用 Chrome/Edge 打开时 Ctrl+F 搜不到字，但同名的 `_result.txt` / `_PD6AIFOCR.txt` 里却有完整 OCR 文字。

本工具把 TXT 里的识别结果**按页码重新写回 PDF**，替换掉错误的旧文字层，让 PDF 重新可搜索、可复制。

### 核心能力

- **按页码对应**：TXT「第 N 页」的内容写入 PDF 第 N 页，不依赖图像坐标
- **竖排古籍风格**：每页文字从右上角起，每行一列，列从右到左（rotate=270），符合古籍版式
- **透明文字层**：不影响看图，可正常复制/搜索
- **彻底清除旧层**：删除内容流中全部旧文字（含残留 TD 块），图像层无损
- **多核并行**：默认 4 线程同时处理多个文件，可调 1~16，处理 400+ 文件大幅提速
- **递归扫描**：选择任意父目录，自动扫描所有子目录配对
- **保留原件**：输出 `XXX_..._fixed.pdf`，不覆盖原文件

### 自动识别的文件配对

| TXT | PDF | 来源 |
|---|---|---|
| `XXX_result.txt` | `XXX_layered.pdf` | CathayOCR Lite 输出 |
| `XXX_PD6AIFOCR.txt` | `XXX_PD6AIFOCR_opt.pdf` | FOCR 工具输出 |
| `XXX_PD6AIFOCR.txt` | `XXX_PD6AIFOCR.pdf` | FOCR 无 _opt 变体（如北洋政府公报） |

其它后缀（`_FOCR_opt.txt`、`_【繁转简】` 等）一律忽略。

## 系统要求

- **操作系统**：Windows 7/10/11 64位
- **GPU 模式**：支持 Vulkan 1.1+ 的显卡
- **CPU 模式**：任意 x64 处理器均可

## 使用方法

### 方式一：独立便携包（推荐，最简单）

1. 进入 `CathayOCR-Lite-Portable\` 目录
2. 双击 **`启动.bat`**，等待主界面弹出
3. 拖入 PDF → 选择语言 → 点运行

### 方式二：源码目录直启

1. 进入 `CathayOCR-Lite\` 目录
2. 双击 **`启动.bat`**
3. 🎯 简单模式：选择语言 → 点运行
4. 🔧 专业模式：更多参数可调（模型、边长、精度等）

## 故障排除

| 问题 | 原因 | 解决 |
|------|------|------|
| GPU 模式黑屏/崩溃 | 显卡驱动过旧 | 更新显卡驱动 |
| AMD 核显高频崩溃 | FP16 加速不稳定 | 切换到 FP32 精度 |
| 自动模式选了 CPU | 未检测到合适独显 | 手动切换为「GPU 模式」 |
| 无法启动 | 安全软件拦截 | 加入信任区或命令行运行查看错误 |
| 进度卡住不动 | 子进程异常 | 检查任务管理器有无残留 ppocr 进程，重启程序 |
| 竖排古籍顺序仍乱 | 未勾选「竖排识别」（v1.2.3 起该选项才真正生效） | 勾选「OCR 选项」中的「竖排识别」后重新运行 |
| 竖排 PDF 搜不到文字 | 竖排文字横排写入超界（v1.2.3 修复） | 勾选「竖排识别」后重新运行 |
| 导出 PDF 搜不到文字 | OCR 像素坐标未换算（已修复） | 重新运行一次即可 |
| TXT 有字但 PDF 搜不到 | 旧文字层错误/超界 | 用附赠的 TXT 文本层写回工具修复 |
