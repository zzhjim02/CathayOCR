# CathayOCR Lite (轻量版) v1.3.0

基于 ncnn Vulkan 的便携式 PDF OCR 工具。CathayOCR 专业版的轻量分支。

## 特性亮点

🚀 **单一引擎，一键启动**
- 仅保留 ncnn Vulkan 引擎，无需选择纠结
- GPU 模式（Vulkan 加速）/ CPU 模式（原生 ncnn，不初始化 Vulkan）
- 支持任意品牌显卡：NVIDIA / AMD / Intel 均可
- 支持 PP-OCR 多版本模型（v3 ~ v6）

🪟 **标准程序启动（v1.3.0 新增）**
- 双击 **`CathayOCR Lite.exe`** 即可启动，像正常软件一样使用
- 独立**运行日志窗口**：实时显示启动过程 / GPU 检测 / 识别进度 / 错误信息
- 日志窗口**白底浅色、默认吸附**在主程序右侧（`CATHAYOCR_DOCK=0` 可改为独立窗口）
- 启动时自动做**硬件自检**（CPU / 内存 / 显卡）并给出推荐结论
- **任务栏只有一个图标**；正常退出时日志窗口停留 5 秒并显示倒计时
- 内嵌软件图标，无需忍受黑框控制台

🪟 **迷你窗口模式（v1.3.0 新增）**
- 处理中点顶部「🗕 迷你窗口」，主界面与日志窗口一起收成**屏幕右下角**的小卡片
- 卡片只显示：当前处理文件名 / 已处理与总文件数 / 进度条，**识别照常进行**
- **处理完成自动还原**；也可点「恢复」、双击卡片、或点任务栏图标手动还原
- 未开始处理时进入则显示「等待用户安排 OCR 任务」
- 卡片可拖动，标题栏「📌」可手动切换置顶（默认置顶，选择会被记住）

🧹 **零残留设计（v1.3.0 新增）**
- 启动器自动清理上次异常退出遗留的临时解包目录，C 盘不再堆积垃圾
- 进程清理只针对**本软件目录内**的引擎进程，绝不误伤电脑上其他正在运行的程序

📦 **极致便携，U 盘即用**
- 自带便携 Python 环境，无需任何安装
- 拷贝到任意目录即可运行（路径可含中文）

🌍 **多语言支持（v1.3.0 重排说明）**

轻量版用 ncnn 的 PP-OCRv6 通用字典，支持与不支持**明确分开**：

| ✅ 轻量版支持 | 说明 |
|---|---|
| 中文 | 繁简体自动识别 |
| 英文 / 日文 | 通用字典直接覆盖 |
| 拉丁语系 | Français、Deutsch、Español、Italiano、Português、Nederlands、Polski、Magyar、Čeština、Tiếng Việt… 40+ 种 |
| 希腊文 | 字典含希腊字符，实测可识别 |
| 多语言混排 | 中·英·日 + 拉丁语系同时排版 |

| ❌ 需专业版 | 原因 |
|---|---|
| 韩文 · 俄文等西里尔文 · 阿拉伯文 · 印地文等天城文 · 泰文 · 泰卢固文 · 泰米尔文 | 通用字典不含这些文字（实测 0 覆盖），轻量版识别会乱码；专业版内置官方分语种模型 |

> 语言下拉里**需要专业版的项会标注「（需专业版）」并灰显不可选**；✅ 支持 / ❌ 需专业版 两类范围写在**下拉的悬停提示**里（界面不常驻大段文字）。

📄 **PDF OCR 专业功能**
- GPU 双实例并行（提升 30~50%）
- 古籍/竖排/复杂排版支持
- 拖放文件处理，批量输出

🛠️ **附赠 TXT 文本层写回工具**（`TXT写回工具\` 目录）
- 批量把 OCR 结果 TXT 写回 PDF，替换无法搜索的旧文字层
- 竖排古籍风格排版、透明可搜索文字、多核并行加速

## ✨ v1.3.0 更新内容

1. **标准程序启动器 + 运行日志窗口**
   - 新增 `CathayOCR Lite.exe` 瘦启动器：双击即启动，弹出独立日志窗口显示运行状态
   - **启动即做硬件自检**：后台检测 CPU / 内存 / 显卡（nvidia-smi、vulkan 运行库、引擎目录），给出推荐结论，不会卡住首屏
   - **白底浅色 + 默认吸附侧边栏**（330px，跟随主窗口移动；设 `CATHAYOCR_DOCK=0` 可关闭）
   - **任务栏只有一个图标**：日志窗口以工具窗口样式运行（设 `CATHAYOCR_LAUNCHER_TASKBAR=1` 可回退旧行为）
   - **正常退出停留 5 秒**并在状态栏显示秒级倒计时；异常退出保持窗口打开以便查看报错
   - 主程序异常退出时日志窗口给出明确提示；任务运行中关闭窗口会先确认，防误触
   - 崩溃信息写入 `CathayOCR_%Y%m%d-%H%M%S.log`，便于排查

2. **修复 4 个 Bug（不改动识别链路）**

   | # | 问题 | 修复 |
   |---|------|------|
   | 1 | 退出时按进程名**全局强杀**引擎，会误杀电脑上其他正在运行的 OCR 程序 | 改为枚举进程完整路径，只结束本软件目录内的进程 |
   | 2 | MuPDF 警告压制用 `dup2` 重定向 stderr，多线程并发时错误输出被**永久吞掉** | 改用 PyMuPDF 官方开关 |
   | 3 | 关窗时若引擎不存在会**白启动 2 个引擎**再关掉 | 仅在实例存在时才关闭 |
   | 4 | 字典与模型不匹配时引擎会在 1~2 次请求后**永久卡死** | 字典跟随实际选中的模型；正常使用路径逐字不变 |

3. **队列改存 PNG 字节（内存优化）**
   - 渲染线程与识别线程之间的队列不再存 base64，内存占用**降约 25%**
   - 引擎实际读到的临时文件逐字节相同，识别结果不变

4. **C 盘零残留**
   - 启动器每次启动自动清掉自己上次遗留的解包目录（带专属标记，绝不碰其他程序的文件）

5. **全新家族风格图标**（纸张 + 取景框，与系列软件统一）

6. **🪟 迷你窗口模式（新增）**
   - 处理中点顶部「🗕 迷你窗口」→ 主界面与日志窗口一起收成**右下角悬浮小卡片**（当前文件名 + 已处理/总数 + 进度条）
   - 未开始处理时进入显示「等待用户安排 OCR 任务」；处理完成或主动恢复时自动还原（保留进入前的最大化状态）
   - 卡片可拖动；标题栏「📌」可手动切换置顶（默认置顶，选择会被记住）
   - 纯界面行为，**不影响正在进行的识别任务**

## 系统要求

- **操作系统**：Windows 7/10/11 64位
- **GPU 模式**：支持 Vulkan 1.1+ 的显卡
- **CPU 模式**：任意 x64 处理器均可

## 使用方法

1. 双击顶层 **`CathayOCR Lite.exe`**（或 `CathayOCR-Lite\CathayOCR Lite.exe`）
2. 日志窗口先弹出，主界面随后自动出现
3. 🎯 简单模式：选择语言 → 点运行
4. 🔧 专业模式：更多参数可调（模型、边长、精度等）
5. 拖放 PDF 文件到列表 → 点运行

> 备用启动方式：`启动.bat`（源码直启，效果相同）

## 故障排除

| 问题 | 原因 | 解决 |
|------|------|------|
| GPU 模式黑屏/崩溃 | 显卡驱动过旧 | 更新显卡驱动 |
| AMD 核显高频崩溃 | FP16 加速不稳定 | 切换到 FP32 精度或改用 CPU |
| 自动模式选了 CPU | 未检测到合适独显 | 手动切换为「GPU 模式」 |
| 主界面迟迟不出现 | 主程序仍在初始化 | 查看日志窗口进度；超过 30 秒再关掉重试 |
| 无法启动 | 安全软件拦截 | 加入信任区或用 `启动.bat` 查看错误 |
| 进度卡住不动 | 子进程异常 | 检查任务管理器有无残留 ppocr 进程，重启程序 |
| 竖排古籍顺序仍乱 | 未勾选「竖排识别」（v1.2.3 起该选项才真正生效） | 勾选「OCR 选项」中的「竖排识别」后重新运行 |
| 竖排 PDF 搜不到文字 | 竖排文字横排写入超界（v1.2.3 修复） | 勾选「竖排识别」后重新运行 |
| TXT 有字但 PDF 搜不到 | 旧文字层错误/超界 | 用附赠的 TXT 文本层写回工具修复 |
